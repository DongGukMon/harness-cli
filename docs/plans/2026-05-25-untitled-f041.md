# Phase 6 Stability — Eval-Commit Empty-Diff & Mid-Session Dirty Tolerance — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make Phase 6 (`verify` + `commitEvalReport`) recoverable in two new failure modes — (a) the eval report regenerates byte-identically after a P7-reject → P5-reopen cycle, and (b) mid-session untracked files (e.g. `.claude/scheduled_tasks.lock`) appear in the tracked repo's working tree.

**Architecture:** Three localized changes in `src/artifact.ts`: `normalizeArtifactCommit` returns `false` (instead of throwing) on empty staged delta; `commitEvalReport` widens its return type to `'committed' | 'unchanged' | 'gitignored'`; `runPhase6Preconditions` returns the list of fingerprints it auto-added to the dirty baseline (`??`-status only, never modified-tracked). Three production callers (`runner.ts`, `resume.ts` x2) treat `'committed'` and `'unchanged'` identically; `verify.ts` persists the auto-extended baseline and emits a new `dirty_baseline_extended` event; `handleVerifyPhase`'s catch block parses precondition throw messages to enrich `phase_end.details.offendingPaths`.

**Tech Stack:** TypeScript (Node 18+), Vitest, pnpm. No new runtime dependencies. No schema migration (`state.dirtyBaseline: string[]` already exists).

### Step 2: Edit `src/artifact.ts`

- [ ] **2.1 — `normalizeArtifactCommit` (replaces existing lines 113–143):**

Two coupled changes:

1. **Reorder so the staged-file guard runs FIRST** (gate-4 P1.1 / spec R1.b): the existing code returns `false` early when `getFileStatus === ''`, which means an unrelated staged file paired with a clean/missing eval report silently skips the throw. Move the `getStagedFiles` check above the `fileStatus === ''` early return so the R1.b throw fires unconditionally when other files are staged, regardless of eval report status.
2. **Empty-diff detection** (R1.a): after `git add`, check whether the staged diff vs HEAD is empty via `git diff --cached --quiet HEAD -- "${filePath}"` (exit 0 = no delta, exit 1 = delta). If no delta, skip the commit and return `false`.

```ts
export function normalizeArtifactCommit(filePath: string, message: string, cwd?: string): boolean {
  try { exec('git rev-parse --show-toplevel', cwd); } catch { return false; }

  // R1.b precedence (gate-4 P1.1): unrelated staged files MUST throw before any early return.
  const stagedFiles = getStagedFiles(cwd);
  const otherStaged = stagedFiles.filter((f) => f !== filePath);
  if (otherStaged.length > 0) {
    throw new Error('Cannot auto-commit artifact: other staged changes exist.');
  }

  // File clean/missing → no-op
  const fileStatus = getFileStatus(filePath, cwd);
  if (fileStatus === '') return false;

  const cwdAbs = cwd ?? process.cwd();
  if (!existsSync(join(cwdAbs, filePath))) return false;

  exec(`git add "${filePath}"`, cwd);
  // R1.a: empty staged delta → skip commit, return false
  let hasDelta = true;
  try {
    execSync(`git diff --cached --quiet HEAD -- "${filePath}"`, { cwd, stdio: 'ignore' });
    hasDelta = false; // exit 0 = no delta
  } catch { hasDelta = true; }
  if (!hasDelta) return false;
  exec(`git commit -m "${message}"`, cwd);
  return true;
}
```

Note on the existing test `'fails when non-target files are staged'` (`tests/artifact.test.ts` line 64): still passes — the test stages `other.txt` while the artifact is untracked, so the new guard still throws on the first check.

- [ ] **2.2 — `commitEvalReport` (replaces existing lines 285–298) — return type widens:**

Per gate-4 P1.2 / spec R1.c + I1: `'gitignored'` is reserved EXCLUSIVELY for the `isPathGitignored` branch. When `normalizeArtifactCommit` returns `false` and HEAD does not contain the report (or `git ls-tree` itself fails), we MUST throw — never silently report `'unchanged'` nor mis-tag as `'gitignored'`.

```ts
export function commitEvalReport(
  state: HarnessState,
  cwd: string,
): 'committed' | 'unchanged' | 'gitignored' {
  const filePath = state.artifacts.evalReport;
  if (isPathGitignored(filePath, cwd)) {
    process.stderr.write(
      `⚠️  eval report path '${filePath}' is gitignored — skipping commit (evalCommit will remain null).\n`
    );
    return 'gitignored';
  }
  const k = state.verifyRetries + 1;
  const message = `harness[${state.runId}]: Phase 6 — rev ${k} eval report`;
  const committed = normalizeArtifactCommit(filePath, message, cwd);
  if (committed) return 'committed';

  // R1.c + I1: 'unchanged' iff HEAD actually contains the report path.
  // Per gate-4 P1.2: any failure of this verification throws, never silently falls back to 'gitignored'.
  let headTreePaths: string;
  try {
    headTreePaths = execSync('git ls-tree -r --name-only HEAD', { cwd, encoding: 'utf-8' });
  } catch (err) {
    throw new Error(
      `commitEvalReport: cannot verify HEAD tree for '${filePath}' (no commit was created): ${(err as Error).message}`
    );
  }
  const headHasReport = headTreePaths.split('\n').some((p) => p.trim() === filePath);
  if (!headHasReport) {
    throw new Error(
      `commitEvalReport: '${filePath}' not committed and not present in HEAD — refusing to report 'unchanged' (I1).`
    );
  }
  return 'unchanged';
}
```

Rationale (gate-4 P1.2 fix): the previous draft fell back to `'gitignored'` on `git ls-tree` failure and on "HEAD lacks report," but spec R1.c reserves `'gitignored'` solely for `isPathGitignored === true`. I1 mandates committed-or-throw when HEAD cannot be confirmed to contain the report. The throw bubbles to existing `eval_commit_failed` catch sites in callers (`runner.ts` ~1336, `resume.ts` ~209), which already log and surface to the operator.

- [ ] **2.3 — `runPhase6Preconditions` (replaces existing lines 191–283) — new return type + `??`-only tolerance + improved messages:**

Signature changes to `(...): { extendedBaseline: string[] }`. Logic changes:

- Step 1 (staged guard): keep filter but rewrite throw to include offending list per R3.a: `Working tree must be clean before verification: staged files outside eval report: ${nonEvalStaged.join(', ')}`.
- Step 2 (porcelain filter): when computing `dirtyLines`, also accumulate `extendedBaseline`. For each line whose XY is exactly `??` AND fingerprint is not in `baselineSet` AND path is not the eval report → append fingerprint to `extendedBaseline` and DO NOT count as dirty (R2.b). - Step 4 (post-cleanup): use union of `baselineSet` ∪ `extendedBaseline` accumulated in Step 2 (R2.c). Same `??`-only tolerance again. Throw R3.c message: `Working tree is not clean after eval report cleanup: dirty paths: ${dirtyLines.slice(0,10).join(', ')}`.
- Return `{ extendedBaseline }` at the end.
- DO NOT mutate the input `dirtyBaseline` array (I3) — `baselineSet` already copies into a `Set`; `extendedBaseline` is a fresh `string[]` declared locally.

```ts
export function runPhase6Preconditions(
  evalReportPath: string,
  runId: string,
  cwd?: string,
  dirtyBaseline: string[] = [],
): { extendedBaseline: string[] } {
  const resolvedCwd = cwd ?? process.cwd();
  const baselineSet = new Set(dirtyBaseline);
  const extendedBaseline: string[] = [];

  // Step 1: Staged guard
  const stagedFiles = getStagedFiles(cwd);
  const nonEvalStaged = stagedFiles.filter((f) => f !== evalReportPath);
  if (nonEvalStaged.length > 0) {
    throw new Error(
      `Working tree must be clean before verification: staged files outside eval report: ${nonEvalStaged.join(', ')}`
    );
  }

  // Step 2: Unstaged/untracked guard with ??-only tolerance
  const porcelainLines = readPorcelainLines(cwd);
  if (porcelainLines.length > 0) {
    const dirtyLines: string[] = [];
    for (const line of porcelainLines) {
      const xy = line.slice(0, 2);
      const linePath = line.slice(3);
      if (linePath === evalReportPath || evalReportPath.startsWith(linePath)) continue;
      const fp = computeFingerprint(line, resolvedCwd);
      if (baselineSet.has(fp)) continue;
      if (xy === '??') {
        extendedBaseline.push(fp);
        continue;
      }
      dirtyLines.push(line);
    }
    if (dirtyLines.length > 0) {
      throw new Error(
        `Working tree must be clean before verification: dirty paths: ${dirtyLines.slice(0, 10).join(', ')}`
      );
    }
  }

  // Step 3: Eval report cleanup (unchanged from current implementation)
  // ... keep existing fileStatus / isStagedDeletion / unlinkSync / git rm branches ...

  // Step 4: Final clean check — union of baseline + extended
  const finalPorcelainLines = readPorcelainLines(cwd);
  if (finalPorcelainLines.length > 0) {
    const evalReportDeleted = isStagedDeletion(evalReportPath, cwd);
    const dirtyLines: string[] = [];
    for (const line of finalPorcelainLines) {
      const xy = line.slice(0, 2);
      const linePath = line.slice(3);
      if (linePath !== evalReportPath && evalReportPath.startsWith(linePath)) continue;
      if (linePath === evalReportPath) {
        if (!evalReportDeleted) dirtyLines.push(line);
        continue;
      }
      const fp = computeFingerprint(line, resolvedCwd);
      if (baselineSet.has(fp) || extendedBaseline.includes(fp)) continue;
      if (xy === '??') {
        extendedBaseline.push(fp);
        continue;
      }
      dirtyLines.push(line);
    }
    if (dirtyLines.length > 0) {
      throw new Error(
        `Working tree is not clean after eval report cleanup: dirty paths: ${dirtyLines.slice(0, 10).join(', ')}`
      );
    }
  }

  void runId;
  return { extendedBaseline };
}
```

function parseOffendingPaths(msg: string): string[] | undefined {
  if (!msg.startsWith('Working tree')) return undefined;
  const markers = ['dirty paths: ', 'staged files outside eval report: '];
  for (const m of markers) {
    const idx = msg.indexOf(m);
    if (idx >= 0) {
      const tail = msg.slice(idx + m.length);
      const parts = tail.split(', ').map((s) => s.trim()).filter(Boolean);
      return parts.slice(0, 10);
    }
  }
  return undefined;
}
